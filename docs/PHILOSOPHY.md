# 設計哲學 (Design Philosophy)

> 寫給**組員**，也寫給 **AI 助手**。  
> **核心角色定位**：本文件定義了專案的「共通溝通語言（Lingua Franca）」。當你或 AI 在討論構想時，AI 的職責是擔任你與這個設計哲學之間的轉譯橋樑，引導你梳理概念並匯出流程圖，**現階段不需急著刻出複雜樣品，重點在於流程與介面清晰**。

## 0. 一句話原則
**LLM 負責判斷，流程與風控由程式鎖住。組員只管自己的構想與外掛，不必懂整張圖。**

## 1. 共通語言與 LangGraph 的角色
- **共通溝通語言 (Lingua Franca)**：將不同組員天馬行空的金融想法，標準化收斂為「觀察 ➔ 處理 ➔ 提供三層資訊（長中短）」的共通格式。
- **State (狀態)** = 全隊共用的黑板，是契約。節點只讀自己需要的欄位、只寫自己負責的欄位。
- **Node (節點)** = 一個做一件事的函式：讀 State，回傳要更新的資訊。
- **Subgraph (子圖)** = 把一群節點包成一個節點，保持主圖簡潔。

## 2. 核心設計原則

1. **草框先行，不急於做樣品**：現階段重點是把流程圖與資訊邊界定清楚，成熟度夠了再做程式對接。
2. **三步走架構**：觀察（看到了什麼） ➔ 處理（怎麼加工） ➔ 提供資訊（給 AI 查閱）。
3. **資訊漸進展開（三層機制）**：
   - 【短】概要（便宜快速，讓 AI 決定要不要深入看）。
   - 【中】關鍵數據與推論點。
   - 【長】原始段落與證據全文。
4. **數值線與文字線的邊界（重要！）**：
   - **文字線**：新聞、財報文字，萃取為三層條目。
   - **數值線（技術指標/量化/ML）**：**切勿將龐大原始數據直接硬塞給 AI**！AI 無法直接看懂海量跨維度數值。應預先包裝成「工具（Tool）」供 AI 依需呼叫，或預先加工成清晰的訊號摘要文字/趨勢圖片說明。
5. **時間是第一公民**：標註發布時間與可見時間，嚴防前視偏差。
6. **攝取與決策分開**：資訊隨時進來，決策每日固定節奏（最多 25 次調倉）。
7. **程式硬鎖規則**：每日調倉上限、風控門檻由程式邏輯鎖死，AI 無權覆蓋。
8. **錯誤隔離**：任何一個分析壞了不拖垮整隊，每天一定產生報告。

## 3. 給 AI 助手的教練引導職責
當組員拿著想法與你討論時，請遵守以下指示：
1. 擔任共通溝通語言的橋樑，協助組員釐清輸入、處理方式與三層資訊。
2. **匯出 Mermaid 流程圖**，視覺化展示該構想在整體架構中的位置。
3. 提醒組員數值指標應包裝為摘要或工具，避免硬塞。
4. 整理為可直接貼進 GitHub `contributions/` 的 Markdown 格式。
